# UI/UX Responsive Design

## 1. Objetivo

Desenvolver interfaces com alto padrão de qualidade visual, funcional e de experiência do usuário.

Toda interface deve ser:

- Intuitiva e fácil de utilizar.
- Visualmente consistente.
- Responsiva em diferentes dispositivos.
- Acessível.
- Organizada e previsível.
- Adaptável a diferentes resoluções e orientações.
- Consistente com a identidade visual do produto.
- Funcional em diferentes formas de interação.

O objetivo não é simplesmente criar interfaces bonitas, mas desenvolver experiências que facilitem a utilização do sistema.

**Uma interface só está bem desenvolvida quando funciona, apresenta informações corretamente e oferece uma boa experiência independentemente do dispositivo utilizado.**

## 2. Inspecionar antes de desenvolver

Antes de criar ou modificar qualquer interface, investigue o que já existe no projeto.

### Inspeção obrigatória

Verifique:

1. O Design System existente.
2. Os componentes visuais compartilhados.
3. Os padrões de cores e tipografia.
4. Os espaçamentos e dimensões utilizados.
5. Os componentes de navegação.
6. Os padrões de formulários.
7. Os estilos de botões, cards, modais e tabelas.
8. Os breakpoints existentes.
9. As regras de responsividade já implementadas.
10. As referências visuais e padrões das demais páginas.

### Regras de reutilização

- Reutilize componentes visuais existentes sempre que apropriado.
- Prefira estender componentes existentes a criar versões duplicadas.
- Utilize os tokens do Design System.
- Reaproveite padrões de layout e navegação.
- Não crie componentes visuais isolados sem verificar se já existe uma solução.
- Não introduza outro padrão visual sem justificativa.
- Não modifique a identidade visual de outras páginas sem necessidade.
- Preserve a consistência entre diferentes módulos da aplicação.

Antes de implementar uma nova interface, compreenda como as interfaces existentes foram construídas.

## 3. Design System e consistência visual

Toda aplicação deve possuir uma identidade visual coerente.

Quando existir um Design System, ele deve ser tratado como referência principal.

### Cores

Evite hardcode de cores diretamente nos componentes.

Não espalhe valores como:

```css
background: #123667;
color: #ffffff;
border-color: #e5e7eb;
```

Prefira tokens semânticos:

```css
:root {
  --color-primary: #123667;
  --color-background: #ffffff;
  --color-surface: #f8fafc;
  --color-text-primary: #172033;
  --color-text-secondary: #64748b;
  --color-border: #e2e8f0;
  --color-danger: #dc2626;
  --color-success: #16a34a;
}
```

O exemplo é ilustrativo. Sempre verifique os tokens existentes antes de criar novos.

### Regras de cores

- Utilize cores semânticas.
- Mantenha consistência entre componentes.
- Evite introduzir cores aleatórias.
- Preserve contraste entre texto e fundo.
- Diferencie estados visuais sem depender exclusivamente das cores.
- Considere os estados hover, focus, active, disabled e selected.
- Respeite os temas existentes, incluindo dark mode quando disponível.

### Tipografia

Mantenha uma hierarquia tipográfica consistente.

Considere:

- Títulos.
- Subtítulos.
- Texto principal.
- Textos auxiliares.
- Labels.
- Mensagens de erro.
- Informações secundárias.

Evite utilizar tamanhos de fonte arbitrários em cada componente.

Priorize escalas tipográficas e tokens já definidos.

### Espaçamento

Utilize um sistema consistente de espaçamento.

Evite valores aleatórios de margem e padding.

Mantenha proporções visuais entre:

- Seções.
- Containers.
- Cards.
- Formulários.
- Botões.
- Elementos de navegação.
- Agrupamentos de conteúdo.

### Bordas, sombras e raios

Mantenha consistência nos seguintes elementos:

- Border radius.
- Espessura das bordas.
- Sombras.
- Divisores.
- Elevação visual.
- Estados de foco.

Não utilize sombras ou efeitos visuais excessivos para compensar problemas de hierarquia ou organização.

## 4. Responsividade: princípio obrigatório

**Toda interface deve ser projetada considerando celulares, tablets, notebooks e monitores grandes.**

Não considere a versão desktop como a única referência de desenvolvimento.

A responsividade deve ser planejada desde o início, e não adicionada apenas quando o layout já está pronto.

### Mobile First

Sempre que apropriado, utilize a abordagem Mobile First:

1. Desenvolva uma estrutura funcional para telas pequenas.
2. Adicione melhorias progressivas para tablets.
3. Expanda a organização para notebooks.
4. Aproveite o espaço adicional em monitores maiores.

Isso não significa que todas as interfaces devam ser iguais em todos os dispositivos.

O layout pode mudar significativamente quando a disponibilidade de espaço exigir outra organização.

### Dispositivos que devem ser considerados

Considere, no mínimo, os seguintes cenários:

| Categoria | Largura de referência |
|---|---:|
| Celular pequeno | 320–375px |
| Celular comum | 376–430px |
| Celular grande | 431–599px |
| Tablet | 600–1023px |
| Notebook | 1024–1439px |
| Desktop grande | 1440px ou mais |

Essas faixas são referências de validação, não breakpoints obrigatórios.

Os pontos de quebra devem ser definidos conforme o conteúdo e o momento em que o layout deixa de funcionar adequadamente.

Não desenvolva exclusivamente para modelos específicos de iPhone, Samsung ou outros dispositivos.

### Comportamento adaptativo

Avalie o comportamento dos elementos em diferentes larguras:

- Containers.
- Cards.
- Grids.
- Sidebar.
- Menus.
- Cabeçalhos.
- Tabelas.
- Formulários.
- Modais.
- Dashboards.
- Gráficos.
- Listas.
- Navegação.

Não basta reduzir o tamanho dos elementos.

Quando necessário, reorganize a interface, altere a hierarquia, transforme colunas em linhas, substitua padrões de navegação ou apresente informações de outra maneira.

## 5. Layouts responsivos

Utilize as ferramentas modernas de CSS para construir layouts flexíveis.

### CSS Grid

Utilize Grid quando precisar de:

- Layouts com múltiplas colunas.
- Dashboards.
- Cards organizados em grades.
- Estruturas com áreas definidas.
- Distribuição bidimensional de conteúdo.

### Flexbox

Utilize Flexbox quando precisar de:

- Alinhamento de elementos.
- Distribuição horizontal ou vertical.
- Grupos de botões.
- Cabeçalhos.
- Barras de ferramentas.
- Componentes com dimensões flexíveis.

### Media Queries

Utilize media queries quando o layout precisar mudar conforme características da viewport.

Exemplo:

```css
.dashboard-grid {
  display: grid;
  grid-template-columns: 1fr;
  gap: var(--spacing-md);
}

@media (width >= 768px) {
  .dashboard-grid {
    grid-template-columns: repeat(2, minmax(0, 1fr));
  }
}

@media (width >= 1200px) {
  .dashboard-grid {
    grid-template-columns: repeat(3, minmax(0, 1fr));
  }
}
```

Os valores apresentados são ilustrativos. Utilize os breakpoints do projeto quando disponíveis.

### Container Queries

Considere Container Queries quando um componente precisar adaptar seu comportamento ao espaço disponível em seu próprio container, em vez de depender exclusivamente da largura da tela.

Isso é especialmente útil para:

- Cards reutilizáveis.
- Widgets.
- Dashboards.
- Componentes compartilhados entre páginas.
- Elementos que aparecem em diferentes áreas da aplicação.

### Dimensões flexíveis

Prefira:

- `minmax()`.
- `min()`.
- `max()`.
- `clamp()`.
- `max-width`.
- `min-width`.
- Unidades relativas.
- Grid e Flexbox.

Evite larguras e alturas fixas quando elas puderem provocar cortes, sobreposição ou overflow.

Não utilize `position: absolute` como solução padrão para organizar layouts.

## 6. Comportamento mobile

Interfaces mobile exigem decisões específicas de experiência.

Não trate o celular como uma versão desktop reduzida.

### Navegação

Avalie:

- Menus adaptados a telas pequenas.
- Navegação inferior quando fizer sentido.
- Menus compactos.
- Hierarquia de navegação simplificada.
- Facilidade de acesso às principais funcionalidades.
- Prevenção de menus que ocupem espaço excessivo.

Não esconda funcionalidades importantes apenas para simplificar o layout.

### Interação por toque

Considere que dispositivos móveis utilizam principalmente toque.

- Disponibilize áreas de interação confortáveis.
- Evite controles muito pequenos.
- Mantenha distância adequada entre elementos interativos.
- Evite depender exclusivamente de hover.
- Garanta alternativas para interações baseadas em mouse.
- Considere gestos apenas quando houver alternativa acessível.

Como recomendação prática, procure oferecer áreas de toque próximas de 44x44 CSS pixels quando o espaço permitir.
